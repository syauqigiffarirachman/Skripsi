# Logbook Skripsi, 11 November 2026

## Kegiatan hari ini
Hari ini saya melanjutkan perbandingan dua cara membuat **tanda tangan digital**: lewat chip keamanan DS28E38 (hardware) dan lewat program biasa di mikrokontroler STM32 (software). Fokusnya ada tiga hal: mempercepat program yang memakai chip, menyiapkan pembanding software yang paling lambat, dan menyiapkan alat ukur untuk pengujian berikutnya.

## Pekerjaan yang diselesaikan

**1. Mempercepat tanda tangan lewat chip DS28E38**
Sebelumnya program menunggu waktu tetap 520 ms setiap kali meminta tanda tangan, padahal chip sebenarnya selesai dalam sekitar 107 ms. Saya mengubahnya:
- Program kini mengecek chip terus-menerus dan langsung membaca hasil begitu chip selesai, tanpa menunggu waktu tetap. Batas aman 520 ms tetap ada.
- Alamat chip disimpan, jadi tidak perlu dicari ulang setiap perintah (hemat sekitar 25 ms). Kalau gagal, alamat dicari ulang dan perintah dicoba lagi.

Hasilnya, satu tanda tangan kini sekitar **190 ms**, dari sebelumnya sekitar 0,6 detik (±3 kali lebih cepat). Setiap tanda tangan diperiksa di komputer dan hasilnya valid. Mode kecepatan tinggi (overdrive) sudah dicoba, tetapi chip tidak membalas sehingga tidak dipakai.

**2. Pembanding software yang paling lambat (Mbed TLS)**
Saya membuat program uji baru di STM32 yang membuat tanda tangan memakai pustaka Mbed TLS dalam pengaturan paling berat, yaitu tanpa optimasi apa pun. Ini dipakai sebagai batas atas waktu untuk cara software. Hasil ukur pada 48 MHz: sekitar **4,9 detik** per tanda tangan, dan semua tanda tangan valid. Sebagai gambaran, micro-ecc (software yang lebih ringan) sekitar 260 ms dan chip DS28E38 sekitar 190 ms. Jadi pilihan pustaka software sangat memengaruhi hasil perbandingan.

**3. Alat ukur daya dan jendela pengamatan**
- Saya menambah pengaturan tiga pin di papan sebagai penanda untuk alat ukur (osiloskop atau pencatat arus): satu saat menandatangani, satu saat papan tidur, satu untuk seluruh jendela pengamatan 60 detik. Aturan tidur dan cara hitungnya sama untuk software maupun chip, supaya adil.
- Saya membuat program komputer untuk menjalankan jendela pengamatan 60 detik. Ada mode normal (permintaan datang berkala) dan mode serangan (komputer terus mengirim permintaan). Ditemukan bahwa papan bisa macet kalau antrean data USB penuh, jadi program penyerang dibuat mengirim satu permintaan setiap kali papan siap.

**4. Estimasi jumlah siklus dengan emulator**
Saya membuat alat di komputer yang menjalankan program ARM dalam emulator, lalu menghitung perkiraan jumlah siklus prosesor untuk beberapa varian pustaka. Perhitungannya dikalibrasi dengan hasil ukur asli micro-ecc di papan, dan tanda tangannya tetap diperiksa di komputer. Ini bersifat perkiraan, bukan pengganti pengukuran di papan.

**5. Perbaikan alat bantu dan penyimpanan**
Program benchmark diperbaiki agar bisa membaca kolom baru (pemakaian memori heap) dan lebih tahan terhadap jeda balasan. Semua pekerjaan hari ini sudah disimpan ke GitHub.

## Kendala
- Pengukuran Mbed TLS sangat lambat (±4,9 detik per tanda tangan), jadi satu rangkaian pengukuran memakan waktu lama.
- Hasil emulator hanya perkiraan dan harus ditandai jelas di laporan.
- Pengukuran arus dan jendela 60 detik belum dijalankan; baru alat dan programnya yang siap.

## Rencana berikutnya
1. Menjalankan jendela pengamatan 60 detik (mode normal dan serangan) pada software dan chip, sambil mencatat arus.
2. Mengukur tanda tangan chip DS28E38 dengan pengaturan yang sama seperti software agar perbandingannya adil.
3. Mengolah semua data menjadi tabel dan grafik untuk laporan.
4. Mencatat catatan clock 48 MHz dan 72 MHz di bagian metode.
