Bacaan sederhana:
- Pada rho = 1 kedua papan **sudah bekerja di kapasitas penuh**: throughput C hampir sama dengan barrage B. Serangan
  10/s tidak menambah tanda tangan yang dikerjakan; kelebihannya hanya dibuang.

  maksimum (laju 1,529/s software, 8,609/s hardware) tidak bisa ditentukan.

## 4. Temuan selama pengambilan data

### 4.1 Kapasitas efektif sedikit di bawah 1/latensi (overhead layanan)
Di K1S-C tiap run tepat 2 permintaan terlewat (TL 97,8 %) walau rho sedikit di bawah 1. Pin PB1 tinggi terus dari
frame pertama sampai akhir jendela (host tidak pernah Stop), jadi bukan biaya bangun. Siklus layanan nyata
= rentang sibuk / jumlah dilayani: **K1S 660,2 ms** (latensi 654,1 ms -> overhead 6,1 ms, sama di C dan B tunak),
**K2S ≈ latensi** (overhead ≈ 0). (Angka awal "K1S B ~663 ms, K2S ~0,5 ms" keliru: terbawa jeda awal, lihat 4.5.)
Overhead = kerja di luar jendela latensi (terima/urai frame, kirim balasan).
Jadi serangan berperiode = latensi sedikit melebihi kapasitas efektif; antrean (1 tertunda) penuh pelan-pelan.

### 4.2 K2S-C kehilangan 0-6 frame per run di penerima
Mekanisme sama dengan 18 Nov (frame mulai saat host pulih dari alarm Stop, penerima mati ~0,3-0,5 ms), tetapi di C
lebih sering: periode serangan hampir sama dengan siklus host, sehingga fase frame bergeser pelan dan berulang kali
jatuh di celah yang sama. Dengan aturan 0,25 %, 3 dari 4 run awal gugur (butuh ~120 run untuk 30 sah). Bukti bukan
salah ukur: frame rusak 0, tiba + hilang = 516-517 = jumlah yang dikirim attacker. Keputusan peneliti: toleransi C
< 1 %. Dua run gugur (hilang 6 = 1,2 %), diganti 3 run tambahan; **semua 31 run sah dipakai** (tanpa memotong ke 30,
sama seperti 18 Nov). Kode: `run_bench.TOL_HILANG`, `analyse(..., scen=...)`; uji `tests/test_kapasitas.py`.

### 4.3 TL K5 dua nilai: efek pembulatan jumlah frame
Blok 1: 91 tiba, 89 dilayani (TL 97,80 %); blok 4: 90 tiba, 89 dilayani (TL 98,89 %). Dalam 60 s hanya ~91 frame
K1S, jadi geser jam attacker ~0,1 % cukup menentukan apakah frame ke-91 masuk jendela. Yang dilayani sama; arus,
energi per tanda tangan, latensi sama (16,39 vs 16,40 mA). rho_nyata K5 0,985 terbaca sedikit rendah karena jeda
~1,4 s sebelum frame pertama ikut dihitung dalam T_obs.

### 4.5 Jeda awal attacker (ditemukan saat menyusun laporan perubahan)
Attacker mengirim frame pertama ~2 periode + 20 ms setelah `>START` (A 2,02 s, B 0,22 s, C K1S 1,33 s, C K2S
0,26 s), jadi rata-rata jendela memuat waktu menganggur di awal. Keadaan tunak (frame pertama .. akhir): K5 CPU tidur
**0,00 %** (jendela 2,22 %), arus 16,71 mA = B hari sama 16,70 mA; K3 18 Nov tidur 0,00 % (jendela 0,38 %).
Interaksi durasi tidur 18 Nov: +20,51 poin (jendela) vs +18,64 (tunak). Rincian dan dampak ke naskah:
`laporan/3_revisi_naskah/perubahan_skripsi_v5_skenario_c_2026-11-27.md`.

### 4.4 Catatan perangkat
- Flash K1S blok 4 gagal sekali: tegangan target terbaca tetapi SWD tak tersambung -> kabel SWDIO/SWCLK longgar,
  dipasang ulang lalu lancar. Selama flash attacker dinyalakan (mode B) supaya host K2S sering bangun.
- Jam attacker bergeser +0,15 % antara sore dan malam (laju B 10,003 -> 10,015 /s). Periode K2S tidak diubah;
  rho K2S-C 0,996-0,998.

## 5. Yang harus diingat saat menulis naskah
1. **C vs B membandingkan hari berbeda** (27 vs 18 Nov). Selisih kecil (mis. I_avg K3 vs K5 -0,34 mA, latensi
   -0,8 ms) sebagian adalah efek hari (jembatan: I_avg -0,08 mA, latensi -0,8 ms untuk K1S). Daya juga terpengaruh
   tegangan USB 5,13 vs 5,22 V: pakai metrik arus (I_avg, I_dyn, Q_lyn) untuk C vs B, dan sebut keterbatasan ini.
2. P_idle C diambil dari IDLE 18 Nov (VBUS lebih tinggi), jadi P_dyn/E_lyn C bias ~-0,2 mW. Q_lyn/I_dyn lebih aman.
3. Perbandingan K5 vs K6 (hari yang sama, ABBA) adalah yang paling bersih.
4. Frame hilang K2S-C dan overhead layanan dilaporkan sebagai temuan perilaku di ambang, bukan disembunyikan.
