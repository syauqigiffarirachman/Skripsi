## Refaktor host: kode bersama dipindah ke `src/host_common/`
Bagian yang sebelumnya disalin di `src/k1_software/main.cpp` dan `src/k2_hardware/main.cpp` (~250 baris masing-masing) kini satu berkas untuk kedua arsitektur, jadi metodenya dijamin identik:
- `host_util.h`: DWT CYCCNT, cetak heksadesimal/milidetik, `parse_u32`, definisi `ser` (USB CDC).
- `host_time.h`: waktu hardware TIM2->TIM3 (1 us, jalan saat WFI), pin status PB1, keadaan permintaan jendela, permintaan sintetis TIM4.
- `host_rx.h`: penerima frame attacker lewat USART2 + DMA1 kanal 6.
- `host_ram.h`: pengukuran RAM puncak (perintah M).
- `host_link.h`: `hl_u32` diganti `parse_u32` dari `host_util.h`.

`host_util.h` di-include SETELAH tabel konstanta kunci di `main.cpp` supaya urutan data di Flash tidak berubah.

### Verifikasi: isi Flash identik bit per bit
Prosedur: build versi refaktor -> stash perubahan sumber host -> build versi sebelum refaktor di folder yang sama (path debug sama) -> kembalikan refaktor.

| Env | ELF sebelum refaktor | .bin sebelum | .bin sesudah |
|---|---|---|---|
| k1_sw | 9b1adf623e29... (= biner tahap D) | c55d8ca31cc0... | c55d8ca31cc0... |
| k2_hw | 00e99ed39d94... (= biner tahap D) | 4df67c4f9975... | 4df67c4f9975... |

- ELF sebelum refaktor sama dengan sha256 yang dicatat di `sesi.txt`/logbook tahap D, jadi sumber yang di-stash memang sumber pengukuran.
- `.bin` sesudah refaktor identik dengan sebelum refaktor, jadi data tahap D tetap sah untuk kode yang di-commit.
- ELF sesudah refaktor berbeda (k1 b24804c62577..., k2 3ff965bb4b22...) hanya karena info debug (nama berkas, nomor baris). **Untuk membandingkan biner host mulai sekarang pakai sha256 `firmware.bin`, bukan ELF.**
- `tools/uji_galat.py` memakai alamat dari ELF k1_sw; karena isi Flash sama, alamat kode/data tidak bergeser.

## Analisis baru sesuai paper v4 (Sub-bab 3.6) - `tools/analisis_d.py` ditulis ulang
Keluaran: `data/analisis/20261116_010513_r0.1/` (rshunt nominal; jalankan ulang dengan `--rshunt` dan `--multimeter` setelah kalibrasi). Perubahan terhadap versi v3: Holm atas 6 perbandingan (bukan per skenario); IK 95 % bootstrap persentil 10.000 resampel (seed 20261116); ukuran efek rasio HW/SW (Welch) atau Cliff's delta (Mann-Whitney), Hedges g hanya info; interaksi = selisih-dari-selisih + IK bootstrap (ANOVA HC3 jadi pelengkap); sekunder K1 vs K3, K2 vs K4; tabel layanan + model utilisasi; Bland-Altman; regresi duty cycle; LOBO; histogram, interaction plot, drift, Bland-Altman; tabel run gugur per sebab; aturan pelaporan persen (rerata SW / U >= 3, U = 5 % x total).

Hasil utama (rshunt 0,100):
- H1a-c: keenam perbandingan tolak H0 (p Holm <= 1,2e-10). Latensi -69,16 % (453,2 ms) di kedua skenario; P_dyn -77,2 % normal / -34,4 % barrage; S_cpu +57,5 / +64,3 poin; E_lyn -77,3 % / -79,9 %. Semua lolos aturan persen (rerata SW / U = 5,6-7,6).
- Interaksi (DD, positif = manfaat HW lebih besar saat barrage): S_cpu +6,80 poin [6,795; 6,809] (hipotesis interaksi v4 2.7 terdukung); P_dyn -5,88 mW dan I_dyn -1,04 mA (manfaat daya dinamis lebih kecil saat barrage, karena K4 melayani 3,3x lebih banyak); E_lyn IK memuat nol; latensi 0,08 ms (praktis sama).
- H4: TL K1 = K2 = 100 % (N_lwt 0); K3 15,04 % (model 15,24), K4 49,25 % (model 49,44); throughput 3,27x.
- Bland-Altman latensi (60/60 run normal dapat dipasangkan per tanda tangan, 1770 pasang per arsitektur): K1 bias +6,06 ms (LoA 5,96-6,16), K2 +0,023 ms (LoA -0,011..0,056). Bias K1 = kerja di luar jendela DWT dalam satu episode bangun (entropi/persiapan), tetap. Barrage tidak dapat dipasangkan (K3 satu pulsa sepanjang jendela; K4 tidur tunggu IC dipotong bangun UART).
- Bland-Altman S_cpu (120 run): bias -0,0013 poin, LoA [-0,0037; 0,0010].
- Duty cycle: K1 R2 0,9933, intersep 59,75 vs P_idle 59,34 mW, P_aktif 94,56 vs 94,79 mW. K2: model tiga keadaan tidak dapat diidentifikasi (W/D = 1,824 di A dan 1,823 di B, kolinear sempurna) -> dipakai U = aktif + tunggu, R2 0,9991, intersep 63,21 vs 62,48 mW.
- Drift: tidak ada blok dengan IDLE awal-akhir > 0,05 mA. LOBO: gain P_dyn barrage 33,8-35,8 %, normal 77,0-77,8 %; latensi dan S_cpu tidak berubah. P_dyn K1/K3 turun ~1 mW sepanjang blok 3 (tegangan USB).
- Gugur: 10 dari 140 run di sesi terdaftar (semua baris USB hilang: cuplikan kurang + checksum; 1 juga tepi kurang) + 4 sesi gugur utuh (18 run).
