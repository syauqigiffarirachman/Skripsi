## 2. Penjelasan kode (explain)

### 2.1 `.githooks/pre-commit` (hook cepat sebelum commit)
- `set -e`: skrip berhenti pada perintah gagal pertama, sehingga commit ditolak.
- `cd "$(git rev-parse --show-toplevel)"`: pindah ke akar repo agar path relatif (`tools/...`) benar dari mana pun `git commit` dipanggil.
- `unset $(git rev-parse --local-env-vars)`: git menyetel variabel seperti `GIT_INDEX_FILE` saat menjalankan hook. Uji yang membuat repo git sementara (`test_provenance`) akan salah memakai indeks repo asli bila variabel itu diwarisi. Daftar variabel diambil dinamis dari git, bukan ditulis tangan.
- `PY=python; command -v python || PY=py`: di Windows kadang hanya launcher `py` yang ada.
- Empat langkah: (1) `compileall` memeriksa sintaks semua skrip, (2) `cek_pemisahan.py` memastikan kode final tidak mengimpor/menyertakan kode dev, (3) `cek_tautan_dokumen.py`, (4) `unittest discover`.
- Bagian akhir: bila berkas staged berada di `src/ lib/ include/ platformio.ini`, build penuh (menit) **tidak** dijalankan otomatis, hanya diingatkan; `CEK_BINER=1` memaksanya. Alasannya: hook harus < 10 detik agar tidak dilewati orang dengan `--no-verify`.

### 2.2 `tools/4_verifikasi/cek_tautan_dokumen.py`
- `RUJUKAN = re.compile(r"(?<![\w/.-])((?:docs|laporan|logbook)/[A-Za-z0-9_./\-]*[A-Za-z0-9_/])")`
  - `(?<![\w/.-])` (lookbehind negatif): rujukan harus berdiri sendiri, bukan potongan dari path lain (mis. `lib/docs/x`).
  - Grup utama menangkap `docs/...`, `laporan/...`, `logbook/...`; karakter terakhir dipaksa huruf/angka/`_`/`/` supaya tanda baca di akhir kalimat (titik, koma) tidak ikut.
- `_berkas()`: memakai `git ls-files` (hanya berkas terlacak, jadi `.pio/` dan `__pycache__` otomatis tersingkir), lalu menyaring `ABAIKAN_BERKAS` (tabel path lama sengaja memuat path usang), `ABAIKAN_AWALAN` (`data/` mentah, `lib/mbedtls/` upstream), dan ekstensi teks.
- `_wajar()`: placeholder seperti `YYYY`, `<...>`, `*` bukan tautan sungguhan, jadi dilewati.
- `cek()`: rujukan dianggap valid bila path ada, atau path+`.md` ada. Mengembalikan daftar terurut tanpa duplikat; `main()` mengembalikan kode keluar 1 bila ada yang putus (itulah yang membuat hook menolak commit).
- Baris `sys.path.insert(... "_jalur.py" ...)`: mencari ke atas folder yang berisi `_jalur.py` lalu mengimpor `ROOT`. Skrip bisa dijalankan dari subfolder mana pun tanpa tergantung working directory.

## 3. Mengapa begitu (why)

1. **Pisah FINAL vs DEV.** Data 18 Nov dipakai sebagai bukti skripsi. Bila penguji bertanya "kode apa yang menghasilkan angka ini?", jawabannya harus satu folder yang tidak ikut berubah saat eksperimen. *Alternatif*: branch/tag per tahap, ditolak karena kode dev dan final perlu dibangun bersama dari satu `platformio.ini`. *Risiko*: dependensi diam-diam final→dev, itulah mengapa ada `cek_pemisahan.py`.
2. **Bukti biner identik, bukan "kelihatannya sama".** Memindah file di embedded bisa mengubah urutan link, path dalam `__FILE__`, dan makro; semuanya bisa mengubah biner. sha256 sama = pindahan terbukti tidak berefek. *Risiko*: path ikut tertanam di biner (asersi, `__FILE__`) sehingga sha256 bisa berubah walau fungsi sama; di sini dihindari/diperiksa. *Alternatif*: hanya membandingkan ukuran `text/data/bss`, lebih lemah (dua biner berbeda bisa berukuran sama).
3. **Hook cepat, build penuh dilewatkan.** Hook lambat memicu kebiasaan `--no-verify`, yang mematikan seluruh perlindungan. Kompromi: peringatan eksplisit plus opsi `CEK_BINER=1`.
4. **Satu tempat untuk urutan analisis.** Prinsip "satu sumber kebenaran" (DRY untuk prosedur). Risiko: bila skrip baru ditambahkan tapi lupa masuk `LANGKAH`, ia tidak pernah jalan; `cek_reproduksi_analisis.py` membantu mendeteksi hasil yang tidak terbentuk.
5. **Tautan dokumen diperiksa otomatis.** Pemindahan 60+ berkas pasti memutus rujukan; pemeriksaan manual tidak skalabel. Regex + `git ls-files` murah dan deterministik. *Keterbatasan*: hanya memeriksa keberadaan path, tidak memeriksa jangkar (`#bagian`) atau isi.
6. **Folder `tools/` bernomor (1_akuisisi → 4_verifikasi).** Penamaan mengikuti aliran data (ADR 0001), sehingga urutan di file explorer = urutan kerja.
7. **Worktree terpisah saat refactor.** `.pio/build` folder utama tidak tersentuh, jadi acuan build lama tetap ada untuk dibandingkan. Catatan di logbook: mengubah `platformio.ini` tetap membuat PlatformIO menghapus `.pio/build` utama, jadi bangun ulang `host_k1_stop`/`host_k2_stop` sebelum flash.
8. **Dokumen menurut audiens.** `docs/` untuk teknis dan belajar, `laporan/` untuk bahan naskah, `logbook/` untuk jurnal kronologis. Pembaca tahu ke mana harus mencari; dokumen tumpang tindih dilebur agar tidak saling bertentangan.

## 4. Konsep yang perlu dikuasai (teach)

### 4.1 Build reproducible dan sha256
Build **deterministik**: sumber sama + toolchain sama + flag sama → biner sama byte per byte. Hash (sha256) adalah "sidik jari" 256-bit; satu bit beda menghasilkan hash yang sama sekali beda. Contoh: `host_k1_stop` berprefiks `2ca6e8d0d861` sebelum dan sesudah pemindahan = bukti identik. Cari: *reproducible builds*, `arm-none-eabi-size`, `-ffile-prefix-map`.

### 4.2 Git hook dan lingkungan git
Hook adalah skrip di `.git/hooks` atau, di sini, `.githooks` lewat `git config core.hooksPath .githooks` (bisa ikut di-commit). Saat hook jalan, git mengisi `GIT_INDEX_FILE`, `GIT_DIR`, dll. Subproses yang memakai git (misal membuat repo sementara di uji) akan membaca variabel itu dan merusak repo yang salah. Solusi: `unset` semua variabel lokal git di awal hook.

### 4.3 Regex lookbehind
`(?<!X)` berarti "posisi ini tidak didahului X". Contoh: `(?<![\w/.-])docs/` cocok pada `lihat docs/README.md` tetapi tidak pada `lib/docs/README.md`.

### 4.4 Exit code dan `set -e`
Konvensi: 0 sukses, bukan nol gagal. Rantai alat (`main()` → `SystemExit(1)` → hook `set -e` → commit ditolak) bekerja hanya bila setiap lapisan meneruskan kode keluar.

### 4.5 Konsep embedded yang menopang proyek (pengingat)
- **Stop mode (STM32F1)**: semua clock domain 1.8V berhenti, SRAM dan register tetap; bangun lewat EXTI/RTC alarm. Arus rendah, tetapi setelah bangun clock kembali ke HSI dan PLL harus diatur ulang.
- **K1/K2 vs K3/K4**: software ECDSA P-256 (mbedTLS) vs offload ke DS28E38 lewat 1-Wire; `S` pada `K1S/K2S` = varian Stop.
- **1-Wire**: satu jalur data dengan pull-up, waktu bit ditentukan slot mikrodetik; Overdrive mempercepat slot. DS28E38 dapat memakai daya parasit dari jalur data (relevan untuk analisis arus deep sleep).
- **INA226 dan shunt**: mengukur tegangan jatuh di resistor kecil (R_eff 0,0821 Ω hasil kalibrasi); arus = V_shunt / R_eff, ditambah koreksi offset.
